# W3-H1 hardware settings and advisory detection — 2026-08-30

Environment: Windows 11 x64, repository `.venv` CPython 3.12.10, local
`main`. Final production implementation is `04c26a6`; this evidence/log
correction is committed separately after that production fix.

The increment keeps the supported lexical vocabulary explicit (`auto`/`cpu`/
`cuda` and the ten documented compute types), rejects invalid values before a
worker starts, and performs CTranslate2 runtime preflight before
`WhisperModel` construction. Detection is a bounded spawn child and is
advisory only: failures use immutable `auto/default` fallback and never rewrite
settings. The GUI uses readonly choices and the retained worker registry; the
CLI exposes `hardware detect --json`.

## Frozen detector check

The normal windowed app bundle was built with PyInstaller 6.22.2. Its existing
launcher always calls the GUI entry point, so invoking `hardware detect --json`
on that bundle did not dispatch CLI arguments; the exact test PID was stopped
after the bounded smoke window with empty stdout/stderr. This is a pre-existing
launcher limitation, not a detector result.

A temporary console-only PyInstaller probe bundled the same source detector and
was removed after the check. It was built with PyInstaller 6.22.2 using the
final production source. The cold, no-parent-preload executable completed the
spawn round-trip under the production 5-second deadline. The exact run
reported `elapsed=6,329s exit=0`; the child log measured
`ctranslate2-imported:2.858`. It returned:

Build command:

```powershell
& '.\.venv\Scripts\python.exe' -m PyInstaller --noconfirm --clean --distpath 'build\w3-h1-probe-final-dist' --workpath 'build\w3-h1-probe-final-work' 'packaging\_w3_h1_probe_final.spec'
```

Run command:

```powershell

```

```json
{"compute_types": ["bfloat16", "float16", "float32", "int8", "int8_bfloat16", "int8_float16", "int8_float32"], "detail": "Local runtime detected: cpu, cuda; 7 supported compute type(s).", "device_capabilities": ["cpu", "cuda"], "fallback": ["auto", "default"], "status": "ok"}
```
Instrumented frozen comparison found the parent CTranslate2 import took
`3.783s`; with no parent preload the child import took `2.795s`, while a
parent-preloaded child took `0.121s`. This measurement motivated the bounded
5-second default and its deterministic fake-clock regression. The normal
windowed bundle still always enters the GUI launcher and does not dispatch
`hardware detect --json`; that is a separate pre-existing launcher limitation,
not a detector failure. No model was loaded and no network was contacted.
