# Вирішення проблем

## Ollama недоступна

### Симптом

Повідомлення вказує, що Ollama недоступна на `127.0.0.1:11434`, або список
моделей порожній.

### Що зробити

1. Запустіть установлену Ollama.
2. Перевірте `ollama list` у PowerShell.
3. Відкрийте **Налаштування → Локальний AI** й натисніть **Оновити**.
4. Виберіть модель і натисніть **Зберегти**.

## Модель Ollama не підтримує аудіо

### Симптом

Програма повідомляє, що вибрана модель не має capability `audio`.

### Що зробити

Установіть або виберіть в Ollama аудіосумісну модель. VOICE Studio не
встановлює й не оновлює Ollama-моделі автоматично та не перемикається на
Whisper без вашого вибору.

## Ollama не повернула транскрипт

### Симптом

Програма повідомляє `Ollama returned no transcript` і не створює порожній
запис.

### Що зробити

1. У **Налаштування → Розпізнавання** виберіть мову, яка відповідає запису,
   або `auto`.
2. Повторіть обробку короткого чіткого фрагмента.
3. Якщо модель не підтримує фактичну мову аудіо, виберіть профіль
   **Локальний Whisper**. VOICE Studio не підміняє движок автоматично.

## Запис для Ollama довший за 30 хвилин

Профіль Ollama зупиняє локальну конвертацію на межі 30 хвилин, не накопичуючи
WAV без обмеження. Виберіть **Локальний Whisper** для довшого запису або
розділіть робочу копію файлу; оригінал не перезаписуйте.

## AI-виправлення не виконано

### Симптом

Транскрипт відкрився, але metadata або повідомлення містить cleanup warning.

### Причина

Перший Ollama-запит успішно розпізнав аудіо, а другий повернув помилку або
невалідний structured output.

### Що зробити

Збережений raw transcript не втрачено. Перевірте Ollama й запустіть
**AI-редагування…** вручну або виправте текст у редакторі.

## Модель Whisper не встановлена

Ця помилка стосується лише профілю **Локальний Whisper**. Відкрийте **Моделі**,
імпортуйте або завантажте сумісну модель, натисніть **Перевірити**, а потім
збережіть її точний ID у налаштуваннях.

## Каталог моделей потребує уваги

Запустіть офлайн-відновлення й перевірте його JSON-результат:

```text
voice-studio models reconcile
```

Неповний каталог моделі залишається на місці для ручної перевірки: програма
автоматично не всиновлює, не переміщує і не видаляє його. Після перевірки
некерований каталог можна видалити лише з підтвердженням користувача:
`voice-studio models remove MODEL_ID --yes`. Пошкоджений `catalog.json`
переміщується в карантин під часовою назвою `catalog.json.corrupt-*`, після
чого каталог відбудовується; пошкоджений маніфест зберігається і ніколи не
видаляється автоматично. Елементи `blocked` у JSON містять шлях і причину,
які потребують уваги.

## Керований запис позначено як відсутній

Ще раз запустіть `voice-studio storage audit` і знайдіть ID транскрипту та
точний шлях у `missing_records`. Аудит працює лише для читання: дрейф моделей та
експортів показано у вкладених об'єктах `model_catalog` і `exports`, але нічого
не виправляється й не видаляється. Експорт `canonical_stale` — лише
консервативний кандидат, який ніколи не видаляється автоматично.

Ця межа стосується саме `storage audit`. GUI і далі примиряє каталог моделей
під час запуску, а кожна команда `models` робить це перед виконанням;
`voice-studio models reconcile` — пряма явна команда.

Спочатку поза VOICE Studio перевірте, що керована копія справді відсутня. Якщо
запис треба лишити в історії без збереженого аудіо, явно від'єднайте лише
відсутнє посилання:

```text
voice-studio storage repair-missing TRANSCRIPT_ID --expected-path PATH --yes
```

Якщо очікуваний шлях не збігається, файл знову з'явився або шлях небезпечний,
команда відмовиться змінювати запис. Успішна репарація не видаляє і не створює
аудіо заново, не змінює текст транскрипту та оригінальний файл користувача.

## Медіафайл не відкривається

Перевірте розширення, наявність аудіодоріжки, локальне відтворення та межі
2 GiB / дві години. Для незвичного codec створіть копію у WAV або MP3, не
перезаписуючи оригінал.

## Налаштування не збереглися

Натискайте **Зберегти**, а не **Скасувати**. Якщо програма повідомляє про
пошкоджений settings JSON, перевірте всі вкладки й збережіть валідні значення.
Після збереження перезапуск має відтворити той самий профіль і моделі.

## Гаряча клавіша недоступна

Кнопка запису продовжує працювати. У **Налаштування → Загальні** захопіть іншу
комбінацію й перевірте системні дозволи вводу.

## Windows SmartScreen

Поточний Test RC не має цифрового підпису. Перевірте джерело ZIP і SHA-256.
Не запускайте файл, якщо джерело або hash не збігаються.

## Відновлення перервано, і історія виглядає порожньою

Якщо відновлення backup було перервано, а поряд зі сховищем видно каталоги
`*.restore-*` і `*.recovery-*`, знову запустіть VOICE Studio. Програма
використає журнал відновлення, щоб детерміновано завершити або скасувати
операцію, і покаже результат у рядку стану. Якщо з’явиться попередження про
журнал, нічого не видаляйте вручну та створіть redacted diagnostics report.
Каталог `*.recovery-*` ніколи не видаляється автоматично; прибирайте його лише
після перевірки історії.

Якщо перерване відновлення стосувалося зашифрованого backup v2 і налаштування
ще не застосовано, під час запуску програма одноразово запитає пароль у
masked-полі. Правильний пароль завершує відновлення. Скасування або неправильний
пароль нічого не видаляє: encrypted sidecar і журнал залишаються, а програма
продовжує запуск; повторіть запуск і введіть правильний пароль.

## Якщо проблема не зникла

Створіть redacted report:

```text
voice-studio diagnostics --export report.json
```

Не додавайте приватне аудіо, transcript text, API keys, backup, database або
повні локальні шляхи.
