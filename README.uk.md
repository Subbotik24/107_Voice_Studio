# VOICE Studio 0.3.0 Test RC

Локальна desktop-програма для транскрипції на macOS Apple Silicon і Windows x64.
За замовчуванням працює локальна Ollama: вибрана встановлена audio-capable модель
розпізнає аудіо й локально виправляє редагований текст. Аудіо, транскрипти,
історія та налаштування залишаються на пристрої. Хмарні функції запускаються
лише після вибору окремого профілю OpenAI та явної згоди.

Це **unsigned Test RC**, а не production release.

Посібник: [Українська](docs/help/uk/quick-start.md) ·
[Čeština](docs/help/cs/quick-start.md) · [English](docs/help/en/quick-start.md).

## Запуск

Потрібен Python 3.11 або 3.12.

```bash
# macOS: попередньо встановіть Python/Tk і PortAudio
./run_mac.command

# Windows 10/11 x64
run_windows.bat
```

На першому запуску створюється `.venv`; наступні запуски не оновлюють залежності.
Програма не показує примусове вікно початкового налаштування AI. Запустіть Ollama
й виберіть одну з уже встановлених моделей із підтримкою аудіо:

```bash
ollama list
voice-studio transcribe recording.wav --engine ollama --ollama-model gemma4:12b
```

Whisper є окремим необов'язковим локальним профілем для точних часових сегментів:

```bash
voice-studio models install tiny
voice-studio models install small
voice-studio models install tiny --from-directory ШЛЯХ_ДО_МОДЕЛІ
```

`tiny` — компактна Whisper-модель, `small` — профіль кращої якості. Для GitHub Release
моделей задайте URL `model-registry-v1.json` через `VOICE_STUDIO_MODEL_REGISTRY_URL`.
ZIP-моделі та ваги не комітяться в Git.

Лаунчери самі не виходять у мережу. Для developer-checkout можна увімкнути
самооновлення перед запуском змінною `VOICE_STUDIO_AUTO_UPDATE=1`: тоді лаунчер
отримує `origin/main` і перемикається на нього, пропускає оновлення, якщо в
папці є локальні правки, і запускає поточну версію офлайн.

## Збережені профілі, мова інтерфейсу та локальна Ollama

У **Налаштування → Профілі** доступні **Локальна Ollama** (типовий),
**Локальний Whisper** і **OpenAI cloud**. Вибраний профіль, модель та інші
параметри зберігаються локально й відновлюються після наступного запуску.

Інтерфейс та вбудована Довідка разом перемикаються між українською, чеською та
англійською. Якщо Ollama працює на стандартній loopback-адресі, поле
**Локальна модель Ollama** показує встановлені моделі з підтримкою аудіо. Для
цього не потрібні API key або згода на передачу даних у хмару.

У типовому профілі Ollama безпосередньо розпізнає мовлення та автоматично
покращує текст локально. Незмінний STT-результат залишається в `raw_text`, а
обробка змінює лише `corrected_text`. Якщо обробка не вдалася, транскрипт усе
одно зберігається, а програма показує зрозуміле попередження. Один Ollama-запит
обмежений 30 хвилинами; для довших файлів використовуйте профіль Whisper.

Окреме редагування також доступне з CLI:

```bash
voice-studio cleanup TRANSCRIPT_ID --provider ollama --model НАЗВА_МОДЕЛІ
```

VOICE Studio не встановлює, не оновлює та не видаляє моделі Ollama. Якщо модель
не завантажується, програма показує помилку локального runtime, щоб можна було
вибрати іншу встановлену модель.

## Робочі сторінки: Огляд, Студія, Словник, Історія

Ліве меню відкриває чотири локальні сторінки — **Огляд**, **Студія**,
**Словник** і **Історія** — поряд із діалогами Моделі, Backup, Налаштування та
Довідка. Перехід між сторінками так само захищений запитом
Зберегти/Відхилити/Скасувати.

**Огляд** рахує статистику по всій локальній історії на пристрої: кількість
записів, завершені й помилкові, розпізнані слова, загальну тривалість аудіо,
середню швидкість, збережені аудіокопії, активність за 7 і 30 днів та
найчастіші мови, движки й моделі. Він читає всі записи, а не лише видимі в
Історії, не робить жодного мережевого запиту, а записи з нечитабельним payload
рахує окремо як невалідні й спрямовує на `voice-studio storage audit`.

**Історія** поєднує фільтри за текстом, датою, мовою, движком, моделлю,
статусом і наявністю збереженого аудіо та застосовує їх до всього сховища ще до
ліміту в 250 записів.

**Словник** — керована сторінка детермінованих замін. Правила зберігаються
локально поряд з іншими даними програми, їх можна імпортувати та експортувати у
JSON або CSV. У профілі локального Whisper терміни правил, позначених як
підказки, додатково передаються в розпізнавання як обмежені per-request hotwords
і не потрапляють у settings, транскрипти, metadata, diagnostics чи logs.

## Інструменти редактора Студії

- **Пошук і заміна** — літеральний Unicode-пошук із лічильником збігів і
  підсвіткою, заміна від курсора з переходом у початок і заміна всіх.
- **Додати до словника** — перетворює виділення на правило керованого словника й
  застосовує його лише до відкритого редактора. Дія недоступна для зовнішнього
  словника лише для читання або поки на сторінці Словник є незбережені зміни.
- **Слова-паразити** — попередній перегляд із контекстом і окремою галочкою для
  кожного збігу; видаляються тільки позначені. Список залежить від мови запису,
  а для `auto` — від мови розпізнавання в Налаштуваннях.
- **Оцінка впевненості** — панель із сегментами, чия оцінка нижча за поріг
  (типово 0.60, лише стан сторінки, ніколи не зберігається), від найнижчої;
  сегменти без оцінки позначені окремо. Це власний сигнал впевненості движка для
  сегмента, а не ймовірність помилки й не заява про точність.

Ці інструменти змінюють тільки текст у відкритому редакторі. До **Зберегти
правки** нічого не потрапляє у сховище, а `raw_text` лишається незмінним.

Панель відтворення під редактором програє **лише збережену керовану копію
аудіо**: play/pause, stop, ±5 с і швидкість 0.75–2×. Зовнішній оригінал ніколи
не шукається й не відкривається; якщо копії немає, панель про це повідомляє.
Швидкість реалізована ресемплінгом, тому пришвидшення підвищує тон. З панелі
впевненості відтворення можна почати з початку сегмента. Відтворення
зупиняється при зміні сторінки чи запису, під час restore і при закритті.

Ці можливості перевірені source/headless на Linux; відтворення на реальному
аудіопристрої та packaged acceptance на Windows/macOS — **NOT RUN**.

## Черга, Розумний текст і папка синхронізації

**Черга** (кнопка в заголовку Студії) транскрибує багато файлів по черзі активним
профілем: додати файли або папку (за потреби з підпапками), Старт/Пауза/
Продовжити, Пропустити, прибрати завершені. Файл з помилкою записує її в рядок,
і черга йде далі; Скасувати позначає поточний файл як скасований і ставить чергу
на паузу; у редакторі відкривається лише останній успішний транскрипт і ніколи
поверх незбережених правок. Кожен файл проходить той самий шлях, що й одиночне
розпізнавання, включно з per-file згодою на cloud для профілю OpenAI. Черга
живе лише в пам'яті й не відновлюється після перезапуску.

**Розумний текст** (четверта вкладка Студії) показує транскрипт абзацами за
паузами, з опційними часовими мітками та ручними мітками спікерів, і експортує
результат у Markdown або звичайний текст. Мітки спікерів зберігаються лише в
metadata запису; `raw_text` і сегменти не змінюються.

**Папка синхронізації** (Налаштування → Синхронізація) — локальна альтернатива
хмарному завантаженню: VOICE Studio пише кожен збережений транскрипт як пару
Markdown + JSON, за бажанням разом зі збереженою керованою копією аудіо, у папку,
яку може синхронізувати обраний вами сторонній клієнт (Google Drive, OneDrive
тощо). Сама програма не робить мережевих викликів, ніколи не читає зовнішній
оригінал, нічого не видаляє з цієї папки, не пише `source_path` і ключі, а шлях
зберігає як розв'язаний абсолютний. Папка має існувати, не бути symlink-ом і
лежати поза каталогом даних програми; ця перевірка виконується при збереженні й
повторно перед кожним записом дзеркала, тому відредагований вручну чи відновлений
файл налаштувань не може перенаправити дзеркало. Видалення запису з Історії не
видаляє його дзеркальні файли. Усе, що потрапляє в цю папку, залишає пристрій за
правилами того клієнта.

## OpenAI — лише за згодою

Ключ береться з `OPENAI_API_KEY` або macOS Keychain / Windows Credential Manager:

```bash
voice-studio cloud key set
voice-studio cloud key status
```

Аудіо не завантажується без `--allow-cloud-upload`; ліміт — 25 MB, без тихого
стискання або поділу файлу:

```bash
voice-studio transcribe recording.m4a --engine openai-cloud --allow-cloud-upload
```

AI cleanup надсилає лише `corrected_text`, а не незмінний `raw_text`; спочатку
друкує proposal, а збереження потребує `--apply`:

```bash
voice-studio cleanup TRANSCRIPT_ID --provider openai --allow-cloud-text
voice-studio cleanup TRANSCRIPT_ID --provider openai --allow-cloud-text --apply
voice-studio cleanup-undo TRANSCRIPT_ID
```

`offline_only` повністю блокує cloud STT і cleanup. Ключ, аудіо, повна відповідь
провайдера та user paths не потрапляють у settings, backup, diagnostics чи Git.

## Test RC

Очікувані assets: unsigned `.dmg` для macOS ARM64 і ZIP для Windows x64, wheel,
manifest і `SHA256SUMS.txt`. Gatekeeper/SmartScreen warnings очікувані через
відсутність підпису. Завантажуйте лише з GitHub Release, звіряйте SHA-256 і не
вважайте RC production-ready.

Для форумного звіту: `voice-studio diagnostics --export report.json`. Не
публікуйте приватне аудіо, транскрипти, API keys, бази даних чи повні user paths.

## Розробка і перевірки

```bash
python -m pip install -e ".[dev,cloud]"
python -m compileall -q src tests
PYTHONPATH=src pytest -q
ruff check src tests
python -m build --wheel
python -m pip check
```

CI виконує ці перевірки на Python 3.11/3.12 для macOS ARM64 і Windows x64, а
також Linux-джобу на Python 3.12 із Tk під Xvfb — саме в такому середовищі
створюються source/headless докази. Набір тестів імпортує `tkinter` на етапі
збирання, тому Python без Tk його не запустить. Живі cloud-виклики з CI свідомо
виключені.

## Дані та приватність

Оригінальний файл користувача ніколи не видаляється. `raw_text` — незмінний
результат STT; редагування й AI-очищення працюють із `corrected_text`. Ключі
API читаються з `OPENAI_API_KEY`, потім з OS Keychain/Credential Manager і не
потрапляють у settings, backup, повідомлення worker-а, diagnostics чи Git.

Буфер обміну — opt-in: `auto_copy` за замовчуванням `false`; інакше копіювання
є явною дією користувача. Історія буфера, менеджери буфера та OS-синхронізація
можуть зберегти скопійований текст. Незбережені правки викликають запит
Зберегти/Відкинути/Скасувати перед навігацією або закриттям. Збереження тримає
TXT/MD і SRT/VTT узгодженими через редагований шар сегментів без створення чи
зсуву таймкодів; `raw_text` і оригінал не змінюються.

Запис з мікрофона належить recorder-у і лежить у приватному кеші програми:
блоки 100 мс через обмежену чергу на 64 блоки, стеля дві години, попередження
про переповнення, відмова від деградованого запису за замовчуванням. Програма
прибирає лише власні тимчасові файли; неоднозначний залишок зберігається і
показується. Ці контракти мають headless-докази; реальний мікрофон,
відключення пристрою, історія буфера ОС і фізичне приймання на Windows/macOS —
**NOT RUN**. Очищення не є безпечним видаленням.

Для форумного звіту: `voice-studio diagnostics --export report.json`. Не
публікуйте приватне аудіо, транскрипти, бази даних, API-ключі чи повні шляхи.

## Резервні копії та відновлення

`voice-studio backup create out.voice-backup` пише plaintext-архів v1: історія,
налаштування, словник і, якщо не вказано `--without-audio`, керовані копії
аудіо. v1 лишається форматом сумісності за замовчуванням і читається як
звичайний ZIP.

Шифрування — явний opt-in: `--encrypt` у CLI або прапорець «Зашифрувати паролем»
у GUI створює архів v2. Пароль запитується інтерактивно (двічі при створенні,
один раз при verify/restore і при відновленні після перерваного restore), ніколи
не приймається через аргументи чи змінні середовища і не пишеться в settings,
журнал відновлення, sidecar, diagnostics чи логи. **Втрачений пароль не
відновлюється.** `backup verify` і `backup restore` розпізнають v2 автоматично;
неправильний пароль — жорстка помилка без plaintext-fallback. Скасування запиту
ніколи не видаляє recovery state.
